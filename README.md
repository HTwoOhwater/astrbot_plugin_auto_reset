# 每日记忆归档与对话换新

指定 QQ 群每天北京时间 **04:00** 归档当前可见记录、导入现有 MemoryCompanion，然后开启新的原生对话。旧对话、人格、关系和长期记忆保留；摘要在后台分批整理，失败任务可以恢复。

这是基于 [Song-yunru/astrbot_plugin_auto_reset](https://github.com/Song-yunru/astrbot_plugin_auto_reset) 改造的开发版 **2.1.0**。实现位于 `feat/daily-memory-rollover` 分支；默认分支可能仍是上游旧版。已做源码接口核对、离线测试和本地浏览器验收，**尚未在真实 AstrBot 实例安装、联调**。

## 侧栏管理界面

本版自带独立管理页面，安装并启用插件、刷新 AstrBot 后台后，会在左侧插件视图区出现 **「每日记忆」**，与陪伴面板、记忆面板属于同一种入口。

页面可以直接配置开关、群范围和时间，查看依赖检查、最近任务、换新/摘要进度，手动排队换新或重试摘要。设置保存后直接生效；有未保存修改时不能执行手动操作。换新与重试都需要确认目标群。

页面使用 AstrBot 自带的视图 bridge 和后台认证，不另开服务端口、不另设账号。未登录后台、插件停止后的旧页面不能调用管理接口；界面不展示原始聊天内容。

**GitHub 推送不等于服务器已安装，也不会自动进入插件市场。** 安装这个开发分支可[下载 ZIP](https://github.com/HTwoOhwater/astrbot_plugin_auto_reset/archive/refs/heads/feat/daily-memory-rollover.zip)，在插件页上传安装并启用，然后刷新后台。不要从默认分支安装旧版，也不要与同名旧版同时放两个目录。

如果侧栏仍未出现，依次确认插件卡片版本为 `2.1.0`、插件已启用、目录中存在 `views/daily-memory/index.html`，然后重载插件并刷新整个后台。插件开关控制是否加载页面，页面里的「启用每日换新」只控制定时任务，两者不同。

## 适配范围

| 组件 | 此版接受的版本 |
| --- | --- |
| AstrBot | 4.29.1 |
| PrivateCompanion（我会永远陪着你） | 6.7.0 |
| MemoryCompanion | 1.10.5 |

三个组件必须启用。只支持共享群会话、原生 local runner、陪伴单人格模式。未知版本、群成员独立会话、多人格或第三方 runner 会停止执行并在状态中说明；不能直接套用陪伴 7.x 或记忆 2.x。

## 最少需要配置什么

先安装本开发分支，再从「每日记忆」页面或插件卡片的配置入口设置：

| 中文配置项 | 技术键 | 填写方法 |
| --- | --- | --- |
| 启用每日归档与换新 | `enabled` | 初始关闭，核对群范围后打开 |
| 生效群聊（完整会话 ID） | `sessions` | 在目标群发送 `/sid`，复制完整 UMO，一行一个 |
| 每日换新时间：时 | `hour` | `4` |
| 每日换新时间：分 | `minute` | `0` |

例如（将示例替换为 `/sid` 的实际结果，前缀不一定叫 `qq`）：

```json
{
  "enabled": true,
  "sessions": ["qq:GroupMessage:123456"],
  "hour": 4,
  "minute": 0
}
```

空名单不处理任何会话，不扫描所有活跃群。群必须已被陪伴插件正常观察到，群记录不存在或同一群存在未归一化的别名时会延后执行。

现有记忆插件还需启用下列设置，并允许目标群捕获：

- `memory_capture.enabled`
- `conversation_memory.enabled`
- `conversation_memory.capture_group_messages`
- `memory_summary.enabled`

这些开关负责平时的持续捕获；本插件不能找回此前没有捕获、且已从近期窗口滚出的消息。记忆召回与注入仍由 MemoryCompanion 自己配置。

保存配置并按面板要求重载后，由 AstrBot 管理员发送 `/auto_reset preview` 检查依赖和范围。首次巡检只登记当前日界，**下一次 04:00 才自动换新**；已存在的未完成任务会继续恢复。手动执行需发送 `/auto_reset now`。

## 管理命令

所有命令仅限 **AstrBot 管理员**，群管理员身份本身不一定具有此权限。

| 命令 | 行为 |
| --- | --- |
| `/auto_reset status` | 查看开关、北京时间、范围、任务阶段及摘要状态 |
| `/auto_reset preview` | 同上，并检查依赖；不会归档、调用模型或换新 |
| `/auto_reset now` | 为当前白名单群排队；命令结束、会话空闲后执行 |
| `/auto_reset retry` | 为当前白名单群重新排队未完成摘要；不重复建对话 |

同一逻辑日最多换新一次，逻辑日从北京时间 04:00 开始。`now` 不会强行重复执行已完成的当天任务。关闭开关会停止后续巡检；它不是对进行中操作的即时撤销。

## 每天如何处理

1. 每分钟检查日界。若普通回复、原生后台任务或已标记的陪伴群记忆整理尚在运行，则延后，不打断它们。
2. 保存当前原生历史、陪伴近期群消息/回复、原生群聊临时记录的不可变原文归档。
3. 将可用文字通过 MemoryCompanion 历史导入接口写入时间线，记录待摘要 ID。导入无法确认成功时不换新。
4. 新建空对话，继承旧人格。移除归档截止点以内的 `recent_messages`、`recent_bot_replies` 和已归档的原生群聊临时缓存，再选择新对话；截止点后新到的陪伴消息保留。
5. 后台按记忆插件自己的批次限制整理摘要，通过时间线 `summarized_at` 标记确认进度。不会将一次模型返回当作全部处理完毕。

**换新完成与摘要完成是两个状态。** 原文已经保存、导入后允许换新；摘要失败不会删除原文，也不会导致第二次换新。连续三次无进展或异常后，摘要任务标记 `paused`，排查后用 `retry` 恢复。记忆插件已有的 `evidence_quarantine` / `dead_letter` 不会被本插件绕过。

程序停机跨过日界，恢复后最多补一次换新，不会连建数个空对话。忙碌会话实际切换可能晚于 04:00；归档边界是实际取得快照的时刻，并非严格在 04:00 截断每条消息。

## 原始记录与恢复

运行数据写入 AstrBot 的 `data/plugin_data/astrbot_plugin_auto_reset/`，不写入插件源码目录：

```text
rollover_jobs.json       # 阶段、对话 ID、待处理摘要 ID
archives/<sha256>.json   # 含完整当前历史与缓存的原文快照
```

归档和任务账本使用临时文件、刷新及原子替换；归档读取校验内容哈希。损坏时停止处理，不静默重建空账本。旧原生对话保留，可从 AstrBot 的对话管理中切回；任务中的新对话带有 `[auto_reset:...]` 标题，供中断恢复时定位。

需要保留这些数据才能恢复任务；本版不自动清理归档，会占用磁盘。归档含聊天原文，应按聊天历史管理其访问权限和备份。Linux 新写文件权限为 `0600`。

常见状态原因：

| 状态/原因 | 处理 |
| --- | --- |
| `session_busy_retry_later` / `session_lock_busy` | 自动等待会话空闲 |
| `companion_background_busy_retry_later` | 等待陪伴群整理结束 |
| `unsupported_*` / `*_contract_missing` | 检查组件版本；不要通过改版本号跳过校验 |
| `companion_group_not_observed` | 先让陪伴插件正常捕获目标群消息 |
| `companion_group_aliases_require_normalization` | 在陪伴插件中解决群别名/重复记录，再重试 |
| `memory_evidence_review_required` | 先在记忆插件中处理隔离证据，再 `retry` |
| `pending` / `paused` | 原始记录保留，摘要未全部完成；排查原因后 `retry` |
| `superseded` | 用户已手动切换原生对话，旧任务不再覆盖选择 |
| `archive_too_large` / `memory_backlog_too_large` | 单次待处理上限 50000 条，停止换新；先处理积压 |

发生中断时会从持久化阶段重试；新对话创建后、写入账本前中断，也会按唯一标题找回它。跨插件存储没有共同事务：陪伴缓冲保存成功但原生选择器失败时，可能短暂出现缓冲已清而选择器未更新；原文仍在归档，后续巡检继续恢复。

## 目前的边界

- 仅移除上述近期窗口。陪伴的群画像、话题/事件记忆、关系、日程仍可能提供过去信息；长期记忆召回也会保留过去信息。
- 原生对话不一定有用户 ID 或原始时间：其文字作为“身份/时间未确认的对话摘录”导入，不伪造个人归属。工具/系统消息和媒体二进制不进入摘要输入，当前原生历史结构仍保留在本地归档。
- 近期窗口和原生对话可能包含重叠内容。稳定消息 ID 防止同一路径重复导入，但无法可靠消除不同来源的语义重复；摘要质量仍依赖现有记忆插件。
- 摘要接口会取该群当前最早的未处理批次，可能包含更早积压及后来捕获的消息，不承诺严格按日生成独立摘要。
- 已核对原生会话锁、活动任务注册表和两个陪伴群整理标记；不能保证所有第三方插件或陪伴自有主动发送任务都遵守同一个锁。真实群中的并发发送、记忆召回质量和插件热重载仍需隔离实例联调。
- 同一数据目录只运行一个插件实例。此次开发不包含服务器安装、启用、重启或真实会话换新。
