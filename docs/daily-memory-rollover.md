# 每日记忆归档与对话换新：改造草案

状态：设计草案，尚未实现、安装或执行。2026-10-25。

## 目标与适配基线

每天北京时间 04:00，仅为明确选中的 QQ 群建立新的对话边界。此前消息继续由现有记忆系统保存、整理、召回；旧原生对话保留，陪伴关系与人格保留。

已核对的目标部署：AstrBot 4.29.1、PrivateCompanion 6.7.0、MemoryCompanion 1.10.5。其他版本必须独立探测兼容性；尤其不能直接套用 MemoryCompanion 2.x 或 PrivateCompanion 7.x 的接口。

本 fork 基于 Song-yunru/astrbot_plugin_auto_reset 的提交 a367e2ad5e3a684aef6fff1039578c79837bbe34。保留上游来源，不为上游未声明许可的代码自行添加许可声明。

## 与原插件的区别

原插件按时间遍历内存活跃会话，通过 update_conversation(..., []) 清空原对话。目标实现应创建新对话并保留旧记录；只处理显式名单，不沿用全局清空操作。

不能仅把定时器改成 04:00：PrivateCompanion 自有近期群消息，即使原生历史换新，也可能重新注入昨日内容。MemoryCompanion 的单次强制总结也只处理有上限的一批，不能将一次调用返回当作全天记忆整理完成。

## 最小配置体验（拟议，尚不存在）

| 用户配置 | 初始值/约束 |
| --- | --- |
| 启用每日换新 | 默认关闭 |
| 生效群/会话 | 必填完整 UMO；空名单不处理任何会话 |
| 每日换新时间 | 04:00；明确使用 Asia/Shanghai |

归档失败保留原对话、等待正在进行的回复、重启恢复与避免重复执行，应作为默认行为，不增加一串必须由用户选择的开关。

## 处理流程

1. 对到期的目标会话获取协调锁，检测正在执行的回复与工具；繁忙时延后，不中断或覆盖新消息。
2. 固化本次边界：逻辑日期、旧对话 ID、消息/事件截止点，以及待归档内容；先持久化再进入后续阶段。
3. 通过适配层核对 MemoryCompanion 已持久化的时间线；截止点之前的消息必须可恢复，待整理任务必须持久化。不能只凭“已开启捕获”认为所有群消息都已保存。
4. 启动或恢复有界总结任务，保留失败及待处理状态；明确区分“原始消息已保全”和“全部摘要已完成”。无法确认原始内容已保全时不切换。
5. 为 PrivateCompanion 建立相同的近期历史截止点。优先采用插件已有且验证过的接口；没有可靠接口则停止并报告，不直接批量修改未知字段或删除画像、关系与长期记忆。
6. 创建并选择新原生对话，继承人格，保留旧对话。切换与陪伴边界需要可恢复的状态机，避免中途失败后形成半完成状态。
7. 持久化完成标记。重启按阶段恢复，避免重复建对话；记录简短状态和失败原因，不在状态日志中写出聊天原文或凭据。

## 开发顺序

1. 先实现只读状态检查与预演：显示目标、时区、下次执行、插件版本及能否安全切换。
2. 为当前三个版本编写小型适配层；对未知版本默认禁用执行。
3. 实现持久化状态机与按会话加锁；用离线替身验证异常恢复。
4. 实现原生新建对话、记忆保全核对和陪伴边界；提供仅管理员可用的预演/执行入口。
5. 在隔离环境试验，再配置单个目标群。安装启用和真实换新须作为单独部署步骤。

## 验收

- 名单以外群聊和私聊不受影响；空名单安全退出。
- 04:00 使用北京时间，延后/停机后恢复不重复建立对话。
- 总结失败、数据库失败或依赖不可用时，不丢失旧消息。
- 回复进行中不切割；边界之后的新消息不被覆盖或纳入昨日归档。
- 原生旧对话可查看，长期记忆可检索，昨日近期消息不被陪伴缓冲重新注入。
- 各持久化阶段中断后恢复结果一致；同一天重复触发只执行一次。
- 管理命令有明确权限检查，默认不开启全局清空能力。
